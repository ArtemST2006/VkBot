# Бот розыгрышей для VK

Небольшой бот для сообщества ВКонтакте по [ТЗ](TASK.md), которое изначально описывало MAX. Пользователь получает промокод партнёра дня, записывается в ежедневный розыгрыш и копит шансы на главный приз. После окончания дня бот сам выбирает победителей и отправляет им уведомления.

Бот работает через Bots Long Poll: сам забирает события VK, поэтому публичный сервер и webhook не нужны. Для хранения пользователей, промокодов, заявок и результатов нужен PostgreSQL.

## Запуск

Понадобятся Docker Compose и сообщество VK. В сообществе должны быть включены сообщения, возможности ботов и Bots Long Poll с событиями `message_new` и `message_event`. Нужны токен сообщества с правами на сообщения и числовой ID сообщества.

```sh
cp .env.example .env
```

В `.env` замените `VK_GROUP_TOKEN` и `VK_GROUP_ID` на свои. Токен не добавляйте в Git. `DATABASE_URL` из примера нужен для запуска с хоста; контейнер бота использует адрес `postgres` внутри Docker Compose.

```sh
docker-compose up --build -d
docker-compose logs -f vkbot
```

Контейнер дождётся PostgreSQL, применит миграции через `goose` и запустит бота. Повторное применение миграций ничего не меняет. Остановить всё можно командой `docker-compose down`.

Если хотите запускать Go-код без контейнера, понадобятся Go 1.26.7 и `goose` в `PATH`. Тогда запустите только базу (`docker-compose up -d postgres`), а бота — через `make run`. Для проверки миграций есть `make migrate-status`.

Миграция с демоданными создаёт 10 партнёрских дней **с даты первого применения по московскому времени** и по пять тестовых промокодов на день. Поэтому кнопки с партнёром работают сразу после первого запуска, а ежедневный розыгрыш можно провести только после окончания соответствующего дня.

## Что проверить в чате

Откройте сообщения своего сообщества и отправьте `Начать` или `/start`. Бот сохранит пользователя и покажет приветствие с [баннером](internal/vkbot/assets/welcome.png) и кнопками. Если VK не примет фото, бот отправит текстовое меню.

| Кнопка | Что произойдёт |
| --- | --- |
| «Получить промокод» | Выдаст один свободный код партнёра текущего дня. Повторное нажатие покажет тот же код. |
| «Участвовать в розыгрыше» | Сразу создаст одну заявку на день и покажет партнёра с призом. |
| «Мои шансы» | Покажет активные дни, партнёров и число шансов на главный приз. |
| «Как участвовать» | Объяснит механику акции. |
| «Правила акции» | Покажет краткие условия демоверсии. |

Получение кода **или** заявка дают один шанс за день. Если сделать оба действия, второй шанс не добавится. Всего можно накопить до 10 шансов. Закончившиеся промокоды не мешают подать заявку.

Сейчас партнёры и коды вымышленные. Ссылки ведут на `example.com`.

## Розыгрыш и призы

Работающий бот раз в минуту проверяет, какие партнёрские дни уже закончились по московскому времени. Для каждого такого дня он один раз выбирает победителей и резерв. После окончания всех дней проводит финальный розыгрыш. Если бот был выключен, при следующем запуске он обработает пропущенные дни.

Победители сразу попадают в очередь сообщений. Работающий бот отправляет уведомление с кнопкой «Получить приз». Победитель нажимает её, отправляет имя и фамилию и соглашается на передачу данных. Если он не ответит в течение 72 часов после доставки уведомления, бот пригласит следующего участника из резерва.

## Что внутри

Путь события простой: **VK Long Poll → обработчик кнопки → сервис → PostgreSQL**. Ответы уходят через VK API. Отдельный цикл отправляет сообщения победителям из очереди.

- `cmd/vk-bot` — запуск бота и фоновых задач.
- `internal/vkbot` — работа с VK, фото и обработчики кнопок.
- `internal/service` — правила участия и получения приза.
- `internal/storage/postgres` — SQL-запросы.

В папке `migrations/` три миграции: исходная схема, демоданные и таблицы розыгрышей с очередью сообщений. Третья также заменяет таблицу `active_days` представлением: активный день считается из выданных промокодов и заявок, отдельно шанс не записывается.

## Проверка кода

```sh
make check
```

Команда запускает `go vet` и тесты Go. Интеграционный тест PostgreSQL запускается при наличии `TEST_DATABASE_URL` и `goose` в `PATH`; он создаёт временную схему и удаляет её после проверки. Реальную отправку сообщений и загрузку фото нужно проверить со своим токеном VK.
