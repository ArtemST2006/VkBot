# Бот розыгрышей для VK

Исходное [ТЗ](TASK.md) написано для MAX. Этот репозиторий временно запускает те же сценарии через сообщения сообщества ВКонтакте, чтобы их можно было проверить в живом чате. Сообщение «Начать» или `/start` показывает меню, кнопка «Как участвовать» объясняет правила и даёт переходы к другим разделам, а «Мои шансы» отвечает количеством шансов. Кнопка «Получить промокод» выдаёт тестовый код партнёра дня и начисляет шанс. «Участвовать в розыгрыше» показывает тестового партнёра; демо-проверка подписки сохраняет заявку и начисляет шанс за день. Правила акции пока отвечают заглушкой.

## Структура

```text
cmd/vk-bot/                          запуск и сборка зависимостей
internal/vkbot/                      Bots Long Poll, маршрутизация и HTTP-вызовы VK
internal/vkbot/handlers/               общие кнопки и контракты
internal/vkbot/handlers/navigation/    старт, меню и неизвестные действия
internal/vkbot/handlers/participation/ участие, проверка подписки и шансы
internal/vkbot/handlers/promo/         выдача промокода
internal/vkbot/handlers/rules/         правила акции
internal/service/                    отдельные сервисы пользователя, промокода и розыгрыша
internal/domain/                     правила и значения предметной области
internal/lib/logger/                 slog: читаемые логи локально, JSON в dev/prod
internal/storage/                    сборка репозиториев в один объект
internal/storage/postgres/           репозитории пользователей, промокодов и заявок на pgx
internal/subscription/               заглушка проверки подписки
migrations/                          SQL-миграции Goose
```

В `cmd/vk-bot/main.go` вручную собираются зависимости: `pgxpool` → `storage.NewRepository(pool)` → `service.New(repo, checker)` → `vkbot.NewHandler(services, client, log)`. `service.New` собирает три небольших сервиса: `UserService` запускает пользователя и считает шансы, `PromoService` выдаёт промокод, `RaffleService` ведёт участие в розыгрыше и обращается к проверке подписки. Каждый сервис зависит только от нужного ему интерфейса репозитория. `vkbot.Handler` проверяет события VK и направляет их в обработчики из `internal/vkbot/handlers/`. Сценарии сгруппированы в `navigation/`, `participation/`, `promo/` и `rules/`. У каждого callback-обработчика есть свой `Action()` и `Handle()`. Сервисы не импортируют VK API. Логгер по образцу GorkyCode использует `LOG_LEVEL` (`debug`, `info`, `warn`, `error`) и `ENV`: при `dev` или `prod` пишет JSON, иначе — читаемый цветной текст.

## Локальный запуск

Нужны Go 1.26.7, PostgreSQL 16, [Goose](https://github.com/pressly/goose) и сообщество VK. В управлении сообществом включите сообщения и «Возможности ботов», затем в «Работа с API» → «Ключи доступа» создайте ключ с правами «Сообщения сообщества» и «Управление сообществом». Включите Bots Long Poll и события «Входящее сообщение» (`message_new`) и «Действие с сообщением» (`message_event`). ID сообщества — положительное число из настроек сообщества, без `club` и минуса. Ключ храните в локальном `.env`, не добавляйте его в Git.

```sh
cp -n .env.example .env
# Укажите VK_GROUP_TOKEN и VK_GROUP_ID в .env.
docker-compose up -d postgres
make migrate
make migrate-status
make run
```

`make run` проверяет и применяет миграции перед запуском бота. Переменная `DATABASE_URL` задаётся в `.env`; пример рассчитан на локальный контейнер из `docker-compose.yaml`. Миграция `00002_demo_partners.sql` добавляет 10 вымышленных партнёров, 10 дней акции начиная с даты её применения по Москве и по 5 тестовых промокодов на день. Ссылки ведут на `example.com`, к реальным аккаунтам они не относятся. Пользователи, заявки и шансы миграцией не создаются. Для новой миграции: `make migrate-create NAME=create_tasks`. Для отката последней: `make migrate-down`; откат демоданных не сработает, если на них уже ссылаются действия пользователей. Откат `00001_initial.sql` удалит все таблицы акции и их данные.

Бот получает события через [Bots Long Poll](https://habr.com/ru/companies/vk/articles/570486/), отправляет ответы через `messages.send`, а нажатия callback-кнопок подтверждает через `messages.sendMessageEventAnswer`. После запуска откройте сообщения сообщества и отправьте «Начать» или `/start`. «Мои шансы» сначала покажет `0 из 10`; после выдачи тестового промокода или регистрации в розыгрыше — `1 из 10`. Оба действия в один день всё равно дают один шанс. Повторное нажатие возвращает тот же код или существующую заявку.

Проверка кода без токена: `make check`. Интеграционный тест PostgreSQL запускается отдельно с `TEST_DATABASE_URL` и Goose; он создаёт и удаляет собственную схему.

## Данные

Начальная миграция создаёт таблицы `users` (VK ID и время первого запуска), `partners`, `partner_days` (партнёр на дату акции), `promo_codes` (пул и закрепление за пользователем), `promo_requests` (каждое обращение для аналитики), `raffle_entries` (подтверждённая заявка) и `active_days` (одна запись на пользователя и день). Следующая миграция наполняет партнёрские таблицы демоданными. Подробные правила записи и планы следующих миграций — в [описании модели данных](docs/storage.md).

Уникальные ограничения не дадут выдать пользователю два промокода или создать две заявки в один партнёрский день. Ключ `active_days (user_id, partner_day_id)` не даст начислить второй шанс за тот же день. Сервис ограничивает показываемое число шансов десятью.

## Ограничения текущего среза

- `postgres.Users` сохраняет пользователя при сообщении «Начать» или `/start` и обновляет `last_seen_at` при повторном запуске. Выдача промокода добавляет запись в `active_days`.
- Демо-партнёры используются для промокода и регистрации в розыгрыше. После десятого дня, заданного миграцией, партнёра на сегодня не будет.
- `subscription.StubChecker` всегда подтверждает подписку только для демонстрации точки расширения.
- Тестовые промокоды нельзя использовать для покупки. Выбор победителей, уведомления и правила акции ещё не реализованы.
- Позиция Long Poll (`ts`) хранится только в памяти. После перезапуска бот начинает читать с текущей позиции VK.

Для продакшена ещё нужны миграции для результатов розыгрышей, согласий на передачу персональных данных и надёжной очереди уведомлений; они описаны в `docs/storage.md`.
